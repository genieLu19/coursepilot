# Устройство CoursePilot

## Загрузка и индекс

`ingest.py` извлекает текст PDF постранично, Markdown и TXT читает в UTF-8. Фрагменты ограничены 1100 символами с перекрытием 160 символов. Это символьное разбиение, а не токенизация. Заголовок Markdown сохраняется в метаданных и добавляется в текст для эмбеддинга. В PDF сохраняется номер страницы; распознавание структуры заголовков PDF не реализовано.

ID фрагмента зависит от курса, имени документа, позиции и текста. Для документа вначале создаются все эмбеддинги, затем фрагменты заменяются одной транзакцией. При сбое старый документ остаётся доступен. Кэш ключуется по SHA-256 от модели и полного входного текста.

## Поиск

BM25 использует Unicode-токены без морфологического анализа. Dense search вычисляет cosine similarity по векторам OpenAI. Для гибридного поиска берутся до 20 кандидатов из каждого списка, затем применяется RRF с k=60. До десяти первых кандидатов можно передать LLM-reranker. В контекст обычно попадают пять фрагментов, при создании плана — до восьми.

Reranker использует Structured Outputs и возвращает порядок существующих ID. Неизвестные ID отбрасываются. Это LLM-reranking, а не cross-encoder. Сходство и ранг не интерпретируются как вероятность корректного ответа. Порог релевантности пока не откалиброван.

## Ассистент

`agent.py` передаёт модели историю текущего курса и четыре функции с JSON Schema. Профиль и курс задаёт приложение; модель не может запросить чужой профиль через параметры инструментов.

Цикл ограничен шестью вызовами Responses API, параллельные вызовы инструментов отключены. При переходе к следующему шагу передаётся полный `response.output`, включая объекты function call. Результат инструмента привязывается через `call_id`. Тест и план в одном пользовательском запросе создаются не более одного раза.

Финальный ответ проходит проверку ID ссылок. Если поиск был выполнен, но подтверждённая ссылка отсутствует, обычный предметный ответ заменяется отказом. Для сообщений об успешно созданном тесте или плане действует отдельная ветка. Решение о том, нужен ли инструмент для конкретного запроса, принимает модель по инструкции. Семантическая проверка всех утверждений не реализована.

## Обучение и память

Структура теста и плана задаётся Pydantic. Приложение проверяет число вопросов, варианты ответа, индекс правильного варианта, существование источников и допустимое время занятий. Сервер хранит ключ теста; клиент получает его только после проверки ответов. Повторная отправка не меняет результат первой попытки.

Прогресс — результаты завершённых тестов и последний сохранённый план. Это не объективная модель владения навыком: качество сгенерированных вопросов отдельно не оценено. Персонализация плана выполняется LLM на основе этих данных. История ограничена последними двенадцатью сообщениями без автоматического суммирования старых диалогов.

## Границы локальной версии

- Курсы и документы общие для одной установки; история и прогресс разделены cookie-профилем.
- Очистка cookies создаёт новый профиль. Синхронизации между устройствами нет.
- SQLite и полный перебор векторов подходят для небольших коллекций; нагрузочный предел не измерен.
- Загрузка документов, генерация и поиск синхронные. Очередь фоновых задач не реализована.
- Браузер не исполняет HTML из ответов: весь текст вставляется через `textContent`.
- Проверка Origin и Host снижает риск запросов с посторонних сайтов при локальном запуске. Она не заменяет авторизацию для публичного сервиса.
